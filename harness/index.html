Media Key Guard for Safari — mechanism harness

How to run each test:
  1. Start Spotify playing music.
  2. Reload this page (⌘R) — fresh media session every test.
  3. Click ONE test button. Wait for sound to finish (unless told otherwise).
  4. Press the keyboard play/pause key.
  5. Note what happened: SPOTIFY paused, or SAFARI replayed/paused the sound, or NOTHING.

T1 — Baseline blip (the villain)

2s beep via plain new Audio(), like a notification. Expect: Safari steals the key. Confirms repro.

T2 — Long tone (YouTube stand-in)

30s tone via <audio> element. Press key while it plays: should pause IT (desired for real media). Press again: resumes?

T3 — Blip, then soft session release

Plays blip, then on end sets mediaSession.playbackState='none' + metadata=null. Does Spotify get the key back?

T4 — Blip, then hard element teardown

Plays blip, then on end: src='', load(), drop reference, plus T3's session release. Nuclear page-level release.

T5 — Blip with disableRemotePlayback

Sets disableRemotePlayback=true before play. Some engines skip Now Playing registration for these.

T6 — Blip routed through AudioContext

Same audio element but wired via createMediaElementSource. Does Safari still claim the key?

T7 — Pure WebAudio blip (plan B, no media element)

Decoded buffer → BufferSource. No media element exists, so Safari should never claim the key.

T8 — Blip → error teardown (src='') → replay same element

Exact T4 teardown (src='' forces a load error) but element kept for reuse. Press key after each play — expect SPOTIFY every time, and replay must still make sound.

T9 — WebAudio reroute (plan B, site-pattern)

Same element reused, but its sound is decoded and played through WebAudio instead — the element itself never plays. Expect SPOTIFY every time, sound audible both clicks.

T10 — Over-length notification + per-site override

8s blip: longer than the default 5s limit, so the guard ignores it and Safari keeps the key. Run it twice — the status bar above shows the limit actually in force.

  1. Default (limit 5s): play, wait for the end, press the key → expect SAFARI.
  2. Popup → set 10 sec → Apply, then reload. Status must read limit 10s.
  3. Override (limit 10s): play again, wait for the end, press the key → expect SPOTIFY.
